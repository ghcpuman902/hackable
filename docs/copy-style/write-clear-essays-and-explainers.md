# Write Clear Essays and Explainers

## Purpose

Use this skill to write polished long-form prose that:

- starts from a meaningful idea rather than raw implementation
- explains complex systems one layer at a time
- connects mechanism to significance
- balances clarity, texture, and authority
- works across essays, write-ups, design thinking, research reflections, and creative-technical case studies

## When to use

Use this skill when the task calls for:

- an article that teaches while still reading like an essay
- a project write-up that explains decisions, not just steps
- a design or product reflection that links interface choices to human consequences
- a technical explainer for mixed audiences
- a research or creative practice note that must stay readable

Do not use this skill for:

- API reference documentation
- dry status reports
- highly formal academic papers
- marketing copy that requires hype, urgency, or sales language
- short X ↔ LinkedIn social sync drafts (those use oxford-chat + Cob voice pack only)

## Core principles

1. Start with the real point. Open with the question, tension, fascination, or ambition behind the piece. Give the reader a reason to care before introducing method.
2. Build meaning before detail. Explain what something is for before explaining how it works.
3. Reveal complexity progressively. Introduce one layer at a time. Let each section answer the question created by the previous one.
4. Tie every mechanism to an effect. For each variable, rule, feature, or choice, explain both what it does and what it helps express, reveal, or solve.
5. Prefer concrete specifics over abstract claims. Use exact examples, small numbers, thresholds, comparisons, and observed outcomes.
6. Keep the prose human. Sound like a thoughtful practitioner explaining real work. Be precise without sounding clinical.
7. Preserve useful imperfection. Briefly mention experiments, trade-offs, failed directions, or tuning work when they clarify why the final choice exists.
8. End by widening back out. Conclusions should return to the larger implication, payoff, or next question, not merely stop at implementation.

## Article architecture

1. Context — why this subject matters
2. Ambition — what the work was trying to achieve
3. Setup — source material, tools, inputs, conditions
4. Base model — simplest structure that makes the rest intelligible
5. Transformations — rules, mappings, modules layered on
6. Tensions and adjustments — hard parts, tuning, competing goals
7. Final form — how the result comes together
8. Evidence — examples, outputs, comparisons
9. Reflection — what this reveals or where it goes next

## Paragraph-level patterns

Short-to-medium paragraphs with one job each. Useful shapes: Claim → explanation → implication; Observation → interpretation → example; Problem → attempted approach → better resolution; Mechanism → behaviour → meaning; Contrast → consequence → takeaway.

Open with a concrete sentence. One idea per paragraph. Lists sparingly.

## Explanation techniques

Layering; functional naming; semantic mapping; bounded specificity; contrast; selective failure; reader reorientation.

## Evidence and image placement

Proof, not decoration. Place after enough context. Rhythm: concept → explanation → evidence → interpretation.

## Tone and diction

British English. Thoughtful, assured, observant, conversational without looseness. Plain verbs, concrete nouns, first person when judgement matters. Avoid hype, corporate optimism, academic scaffolding, slang that dates.

## Anti-patterns

Opening with implementation before stakes; listing steps without why; abstract praise instead of evidence; over-explaining; lab notebook; burying the idea under jargon; ending on tooling.

## Workflow

1. Define the central idea in one sentence
2. Identify the reader's path (questions in order)
3. Gather proof
4. Choose the base structure
5. Group logic into layers
6. Draft the opening late
7. Tighten paragraph by paragraph
8. Check transitions
9. Place evidence deliberately
10. Rewrite the ending for significance

## Quality checklist

Opening creates interest before method; clear through-line; each section has a job; mechanisms named; technical points tied to meaning; enough specifics; jargon limited; evidence where needed; conclusion widens; prose sounds like a person thinking clearly.

## Final instruction

Write so the reader can track three levels at once: what the work means, how it operates, what evidence shows it working. If one is missing, the piece will feel shallow, opaque, or ungrounded.
